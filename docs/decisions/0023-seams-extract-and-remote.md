# 0023. Cut seams where calls cross, extract interfaces by retyping injected dependencies, and generate remote boundaries from raw string templates

- Status: accepted
- Date: 2026-09-26
- Spec section: `docs/spec/commands/seams.md`

## Context

The spec describes `seams`, `extract interface`, and `remote` by method and output. It
leaves these open:
- what counts as a clean entry point for the minimum cut, and which of several minimum
  cuts to report
- how seams are scored
- which caller declarations `extract interface` retypes, and how it proves the edit safe
- how a net10.0-windows host runs an implementation whose project targets net48
- how DTOs are named and mapped, and what the wire format is
- which template engine the scaffolding uses (`docs/spec/00-architecture.md` asks for an
  ADR)
- whether `--transport grpc` and `--rewrite-new` ship now

## Decision

- **Seams.**
  - The graph is the project's named types. Its edges are references from members,
    weighted by how many members of the source type make them.
  - Taint starts at types that use an unportable symbol. It spreads to types that
    inherit from a tainted type or expose one in a public or protected field, property,
    method parameter, or return. Constructor parameters do not spread taint, because
    that is where the interface goes. Calls never taint.
  - Strongly connected components with a tainted type are tainted whole.
  - Clean entry points are clean types that nothing else in the project references.
  - Edmonds–Karp finds the maximum flow. Among the minimum cuts, `seams` reports the one
    closest to the taint: the tainted side is everything that still reaches the sink in
    the residual graph. This keeps interfaces on the unportable types rather than on
    their callers.
  - Score = (share of members that are wire-friendly and not static)
    / (1 + 0.1 × (members − 1)), times 0.8 when the boundary type is not an articulation
    point, rounded to two places. Seams are ranked by member count, then caller count
    (more first), then wire-friendly member count (more first), then boundary type name.
  - `extraction.moveToProject` is `ASSEMBLY.Windows`.
- **Extract interface.**
  - Members come from the seam (`--from-seams FILE#ID`), from `--members`, or are every
    public instance member.
  - The interface is written next to the type, with fully qualified types so it needs
    no usings, in a block namespace so it compiles under C# 7.3.
  - A caller's constructor parameter, field, or property of the concrete type is
    retyped only when everything done through it is on the interface.
  - A parameter that is stored into a field or property is retyped only when that field
    or property is retyped too. This is decided as a fixpoint.
  - `new` is left alone and reported (OFR4010).
  - The edited project is compiled in memory first. New errors, a stale file, or an
    existing file refuse the edit (OFR4012), and nothing is written.
  - `--rewrite-new` is deferred. Replacing `new` with resolution needs a composition
    root that Offramp cannot infer.
- **Remote host.**
  - `--host-framework auto` computes the implementation's file closure: its files and
    the files of every project type they use, transitively. It compiles that closure in
    memory for net10.0-windows against the reference assemblies of
    Microsoft.Windows.Compatibility and the project's own packages, resolved by the SDK
    and NuGet as in `audit api`.
  - If the closure compiles, the host is net10.0-windows. It compiles those files as
    `Compile` links, so the user's project is not edited and the host still builds once
    the files move.
  - Otherwise the host is the net48 fallback (OFR4022), which references the project.
  - Types from other projects make the trial fail. That is conservative: the net48 host
    handles them.
- **Wire.**
  - One POST per member at `Interface/Member`, with overloads numbered.
  - Each member gets a request class with PascalCase properties.
  - Results travel as JSON in the body. `void` and `Task` answer 204.
  - Enums and POCOs get `NameDto` copies in the contracts project. Collections travel as
    `List<T>` and string-keyed maps as `Dictionary<string, T>`.
  - The host and the client each compile their own mapping class, because the
    netstandard2.0 contracts cannot see net48 types.
  - Newtonsoft is configured to match System.Text.Json's web defaults: camelCase
    properties, dictionary keys left as they are.
  - Errors become problem details on both hosts. The client throws
    `RemoteInvocationException` with the title and detail.
- **Generated projects.**
  - Package versions are pinned in `rules/scaffold-packages.yml`, so generation is
    deterministic.
  - Under central package management, generated projects opt out with a comment.
  - C# files carry an `<auto-generated>` header, so the user's analyzers and nullable
    settings do not fail their build.
  - Nothing existing is edited. A non-empty target directory refuses generation
    (OFR4021).
  - Adding the projects to the solution is a printed next step.
- **Templates** are C# raw string literals, with no template engine dependency.
- **Round trip.** The test runs the host in-process with `WebApplicationFactory` on
  every OS, not only Windows, with a stand-in implementation. It needs no Windows API,
  and it catches wire mismatches on every platform.
- **`--transport grpc` is deferred.** The option accepts `http-json` only, and OFR4030
  stays reserved. The M9 roadmap entry does not list gRPC, and a `.proto` generator is a
  project of its own.

## Alternatives considered

- Multi-targeting the implementation's project (`net48;net10.0-windows`) for the host.
  This edits the user's project, and the net48 references (`System.DirectoryServices`
  from the GAC) need conditions that Offramp would have to write.
- A `ProjectReference` from a net10.0 host to a net48 project with
  `AssetTargetFallback`. It builds, then fails at run time on framework assemblies.
- Scriban templates. Another dependency and another language to review. Raw string
  literals are checked by the compiler and are easy to diff.
- Retyping every use of the concrete type in a caller. Local variables and `new`
  expressions would then need a factory. Parameters, fields, and properties are where
  injection already happens.

## Consequences

- The host's linked files and the user's project compile the same source twice. After
  `move plan` moves the tainted types into `NAME.Windows`, the links should become a
  `ProjectReference`. Regenerating does that.
- Synchronous interfaces block on HTTP (OFR4020). `--async-variant` gives callers a way
  out without changing the interface.
- The Dockerfile defaults to Nano Server, as the spec says, and documents the Server
  Core switch for implementations that need the Active Directory client or GDI+.
